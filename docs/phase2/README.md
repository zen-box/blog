# 阶段 2：全局轻音乐播放器验收

2026-10-01。阶段 2 已在既有前台布局和后台设置页实现，播放器默认关闭，不自动播放；音频只有读者明确点击播放才下载。没有加入未经授权的实际音乐。测试使用本地自生成正弦音频，不修改真实 `data/`。

## 验收证据

- 临时数据库 `phase2-ui-data` 从现有迁移升级，新增曲目表；三份自生成 MP3、M4A、Ogg 文件经真实上传服务保存，三种格式均成功读取曲名、作者、专辑、内嵌封面和时长。
- Chromium 1440 × 1000 / 390 × 844，亮色／暗色共四组合：各 11 项播放测试及 3 项管理检查，共 47 项通过。播放器与后台音乐页各四次 axe 扫描均 0 违规，运行时错误 0，整页无横向溢出。[截图](screenshots/)共 8 张，四组合各一张播放器和后台音乐页。
- 真实播放三种格式、歌词滚动、音量／列表循环／单曲／随机、Media Session 播放／暂停／切歌、进度 seek、跨页同一 audio 继续播放、刷新不自动播放且恢复记忆位置、文章 `::audio[…]` 接管和互斥均通过。四组合共观察到 28 次由用户操作触发的音频请求；首屏和只展开播放器均为 0 次。
- 补验 10 项通过：手机入口开关、延迟加载播放器代码、默认音量、真实音量淡入／切歌淡变／淡出、无歌词封面和律动、Media Session 定位、关闭背景音乐仍可播放文章音频、减少动态效果关闭律动动画。
- 后台真实新增、编辑作者并保存、读取、排序、启停及删除通过；浏览器上传后自动填写音频信息通过。匿名接口 401、跨站来源 403、非法音频地址 400。
- `node --import tsx scripts/check-music.ts` 通过：LRC 多时间戳及偏移、三种播放模式与随机不重复、恢复状态校验、URL 拒绝测试。Webpack 生产构建、TypeScript、ESLint、Prettier、postbuild、差异检查通过。

## 行为约束

- 访客不会触发 AI；音乐与文章音频共用一个音频实例。上传保留原音频文件，封面保存到现有媒体库；外部音频地址由管理员自行配置，服务器不会抓取该地址。
- 设置中独立保存播放器开关、默认低音量和手机端可见性。后台曲目记录作品作者、来源和授权协议；播放面板展示署名和授权链接。列表中的禁用曲目不下发给访客。实际版权音乐需管理员自行核实授权后上传。
- 手机测试为 Chromium 触摸模拟，Media Session 验证的是浏览器回调，不等同于物理手机锁屏／耳机设备测试。本机 Turbopack pnpm junction 权限问题仍通过 Webpack 构建规避；未构建或推送 Docker 镜像，也未打标签、部署或使用真实站点数据。
