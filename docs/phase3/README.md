# 阶段 3：读者看到的 AI 内容

阶段 3 包含持久化后台任务、文章开头的 AI 摘要和经作者确认的测评速览。继续使用现有主模型、Markdown 编辑器、存储和站点样式。

2026-10-01 已完成本地验收。检查汇总见 [results.json](results.json)；另有 16 张截图，没有放进仓库。

## 使用方式

1. 在后台「设置 → 读者 AI 内容」启用阅读增强。自动摘要默认关闭；开启后，首次发布或正文变化会加入摘要任务，仅修改标题或标签不会重复调用。
2. 保存文章后，在编辑器打开「读者 AI」。可主动生成、手改、保存、清除或重新生成摘要。此操作不会发布草稿；有未保存改动时需先保存。
3. 点击「提取测评指标」，核对源报告行号、勾选指标、修改结论，再点击「确认并保存速览」。提取建议和未勾选指标不会保存为公开数据。
4. 在「后台任务」查看最近 100 个任务和状态计数。等待、生成中或延迟重试的任务可取消；失败和已取消任务可手动重试。

## 行为与实现

- `reader-ai` 设置独立存储，不覆盖 AI Key、音乐或一般站点设置。公开页面只读取已保存且与当前正文哈希一致的结果，访客访问不会触发 AI。
- `0008_reader_ai.sql` 创建 `reader_insights` 和 `background_jobs`，保留已有内容、历史和音乐数据。任务只存文章 ID、正文哈希、修订号及授权来源，不存会话、Cookie、Key 或正文。
- Drizzle 配置同时扫描主 schema 与 reader schema。CLI 导出确认新表及原音乐、文章、版本历史表全部包含，避免后续迁移遗漏新表。
- worker 从 Node instrumentation 启动，构建期间跳过。状态、尝试次数、可执行时间和租约持久化；SQLite 原子领取、心跳和所有权令牌防止重复提交。进程中断后租约到期可恢复，默认最多尝试 3 次，错误延迟指数增长。
- 通用任务分派支持注册不同类型的处理器，后续语音任务可复用领取、心跳、取消、重试和恢复机制；本阶段处理摘要，阶段 4 的语音合成保持未完成。
- 文章、版本历史和自动入队使用同一事务。入队失败会回滚文章及历史，避免内容已保存却误报失败。重试刷新正文哈希及去重标识，正文 A → B → A 不会被旧任务阻塞。
- 摘要沿用 undici 出站、OpenAI／Anthropic 流解析、主模型、思考与 Key 过滤、超时取消和用量统计。后台能力仅供受信任 worker，原管理员会话、同源与普通外链 SSRF 检查保留，代理失败不直连。
- 正文哈希防止旧结果覆盖新正文，摘要修订号防止生成结果覆盖作者刚保存的手改内容。正文变化后过时摘要和速览暂不公开，失败保留已有有效结果。
- AI 摘要滚动进入可见区域后约 900ms 逐字显示；未显示部分保留排版空间，屏幕阅读器始终获得完整文本，减少动态效果时直接显示。
- 测评提取从 NodeQuality／Check.Place 文字报告确定性读取硬件、性能、IP、流媒体和三网数据。服务端保存时重新核对所选指标，不接受客户端伪造数值。转义 ANSI 和空格实体沿用终端清理，多行流媒体表格包含服务商、状态、地区及方式依据。
- 图片形式的报告没有可提取文字时会跳过，不推断或编造指标。原文行号保留，读者卡片可展开查看依据。

## 首页开发模式错误

首页动画曾用模块级导航状态初始化 React 状态，服务端与客户端可能得到不同的初始 motion 样式。`navigation-state.tsx` 改为 `useSyncExternalStore`，服务端快照固定为 `false`，客户端订阅导航状态。

使用独立临时数据库运行实际 Next dev／Turbopack：首页首次打开、站内导航返回、导航后刷新均通过，未捕获 hydration 或页面运行时错误。该修复已随阶段 2 本地提交 `7665443` 保存。


`check:reader-ai` 在独立临时数据库和本地 HTTP 模拟服务中检查持久化、原子领取、跨进程互斥、租约所有权、心跳、中断上限、取消、延迟重试、超时、正文与手改修订围栏、双协议、用量、访客纯读取、测评确认、签名管理员会话和同源接口。还覆盖文章／历史／入队事务回滚、标题变化不入队、正文恢复去重、转义终端及多行表格。脚本不调用真实付费模型。

实际执行使用包内真实 Node 入口，避开本机 pnpm `.bin` junction 问题；生产构建使用 `next build --webpack` 并执行 postbuild，19 个静态页面生成成功，standalone 产物就绪。
